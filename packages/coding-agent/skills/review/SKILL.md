# Review

A review reports problems. It does not rewrite, and it does not propose fixes in place of the finding.

## When this applies

- The user asks for a review, a critique, a second opinion, or a deep check.
- You are about to call a draft finished and want a second pass.

## Workflow

1. MUST read [review-lenses.md](references/review-lenses.md) before starting.
2. Pick the lenses that actually apply to this artifact. A card with no macros does not need the macro lens; a lorebook does not need the prose lens. State which lenses you ran and which you skipped, and why.
3. Run each chosen lens independently. A lens that is out of scope reports nothing rather than padding.
4. Report concrete findings with a location. NEVER report a verdict without one.
5. You MUST NOT rewrite the draft during a review. The user asked for findings; findings are what they get.

## Reference files

- [review-lenses.md](references/review-lenses.md) — the four lenses, what each one checks, and the format each finding takes.

## Notes

- Read-only lenses only. A review never edits the card.
- Merge the lens findings under one heading each. A finding from two lenses is one finding, not two.
