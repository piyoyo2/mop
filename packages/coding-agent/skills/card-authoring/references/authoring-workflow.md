# Authoring workflow

The box-by-box pass. Each box answers one question, and the order is the order the questions depend on.

## 1. Concept

Before any prose: who is this character, and what is the situation? One question to the user if it is not clear. Everything below is downstream of this.

If the user has library material — a world, a saved idea, a voice profile — ground the card in it now, and confirm the match with them before you read it.

## 2. Personality

**Question:** who is this person, stated so a reader can act against it?

- Traits, not adjectives. "Determined" is an adjective; "will burn the bridge rather than admit she was wrong" is a trait.
- The box should answer how the character behaves under pressure, not how they look.
- Address the user by role or by macro, consistently.
- Include the flaws. A card with no flaws is a sticker.

**Budget:** see `token-economics`. The permanent pair lands in the sweet spot.

## 3. Scenario

**Question:** what situation is the card set in, right now?

- Present tense, scene verb: sitting, standing, eating, arguing, fighting, walking into, currently at, in.
- A situation, not a moment. A moment is frozen; a situation can move.
- Give the user a place in it — a task, a stake, a reason to be there.
- No backstory dump. The backstory belongs in the library, or in a lorebook entry.

## 4. Opening Message

**Question:** what does the user read in the first ten seconds?

Read `opening-message.md` before writing. Start in motion, place the user, end on a step-in.

## 5. Example Dialogue

**Question:** what does this character sound like?

- Demonstrates voice. It does not advance the story.
- Show the register under different pressures — a joke, a refusal, a slip.
- Keep it short. The point is the voice, not the plot.

## 6. Lorebook

**Question:** what does this character need that does not belong in a permanent box?

Only when the answer is non-empty. A lorebook is offload, not ceremony. Read `lorebook` before writing one, and propose it rather than creating it.

## 7. Checks

Before showing the draft:

- Structure: required boxes present, headers recognized.
- Budget: permanent pair in the right band; lorebook hub and entries in band.
- Macros: no spaced, unknown, or collapsed macros.
- Rubric: the draft passes `anti-slop`.

Then show the draft. Do not write it anywhere yet.

## 8. Save

The card goes where the user wants it. The library is separate, and saving to it follows `lore-library`.
