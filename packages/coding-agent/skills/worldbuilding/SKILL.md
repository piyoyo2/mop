# Worldbuilding

A world is a system, not a list of facts. Everything in it has to constrain something else.

## When this applies

- The user asks for a world, a setting, a faction, or a history.
- The user wants an existing world expanded or checked for consistency.
- The result should end up in the lore library.

## Workflow

1. Establish the premise and its constraints before you write anything. What does this world make difficult or expensive that a normal world does not?
2. MUST read [world-model.md](references/world-model.md) before drafting.
3. Draft the world in dependency order: rules, then geography, then factions, then people, then history. Each layer constrains the next.
4. Read it back for contradictions. A world where magic is cheap and one where it costs memory is two worlds; you shipped one.
5. Save with the `lore-library` skill. NEVER write the world straight to disk.

## Reference files

- [world-model.md](references/world-model.md) — the layers of a world, the questions each layer must answer, and the no-slop bar for world prose.

## Notes

- A world with no costs is a wallpaper. Every capability needs a limit, and every limit needs a cost someone pays.
- Name things. A world described entirely in the generic stops being a place.
