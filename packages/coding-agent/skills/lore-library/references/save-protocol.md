# Save protocol

Saving into the library is a sequence, and every step of it is a decision the user makes.

## Steps

1. **Decide what is being saved.** A world, a topic note, a saved idea, or a voice profile each go in a different place. Read `library-layout.md` before choosing.
2. **Choose the name.** kebab-case, descriptive of the content. Propose it to the user.
3. **Show the content.** The user sees what is going into their library before it is written.
4. **Confirm the path.** State the full path. Wait.
5. **Write it.**
6. **Confirm the write.** Report the path that was written.

## Never

- **Never overwrite silently.** If a file already exists at that path, stop and ask. Offer to write alongside it under a different name, or to replace it — the user picks.
- **Never save a draft.** The library holds what the user decided to keep, not the intermediate states of a conversation.
- **Never save something the user did not ask to save.** If a world emerged while writing a card, that is not a reason to write it to the library. Offer.
- **Never write outside the library.** The library is the only place mop puts durable material.

## Format

A `#` heading naming the entry, then the content, written so it makes sense read on its own — months later, by someone who was not in the conversation.

## A saved idea

An idea is not a smaller world. It is a premise with enough specificity to be picked up later: the character, the situation, the one detail that makes it this character and not a generic one.
